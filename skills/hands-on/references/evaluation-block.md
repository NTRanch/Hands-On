# The Evaluation block — template and rules

Every record in `CAST.md` ends with an Evaluation block: the
prototype contract for the level. It names what the level
exists to put in front of the Owner's hands, in his three
judging channels plus the mechanic, and it carries the
verdict field he rules on by playing.

## Template

```markdown
**Evaluation**

- **Animation to judge:** <the loops and expression work this
  level prototypes; eye behavior through the climax included;
  judged against the bar named in CAST.md's header>
- **Sound to judge:** <the sounds this level prototypes;
  buildup audibility and per-event vocal sync included. The
  build has no recorded audio yet — this field is the spec
  the audio prototype is built against>
- **Mechanic to judge:** <the system the player learns by
  playing; where one genuinely applies, the Torogao-pipeline
  competence the mechanic exercises>
- **Verdict:** pending — Owner play
```

## Rules

1. The verdict field is verbatim `pending — Owner play` on
   every record until the Owner plays the piece. No agent
   fills it in, softens it, or pre-judges it.
2. Silence is not a keep: an unplayed piece has no verdict,
   and an unruled piece does not graduate.
3. Each field names something *playable*. "Animation to
   judge" that cannot be played yet names the prototype to
   build, in ramp order — it never describes a text proxy as
   if it were the animation.
4. One block per record, in the record, amended in place as
   prototypes land. The verdict history belongs to the
   repo's memory (`.ai/memory/`), not to edits that rewrite
   the block's past.
